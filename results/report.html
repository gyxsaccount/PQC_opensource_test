迁移点4 · 口令哈希 (Realm)src/PasswordHashPqcTest.javaorg.eclipse.jetty.util.security.Password / Credential
▼ 改造前（弱哈希，量子不安全）
- Credential md5 = Credential.getCredential("MD5:" + md5Hex); // 128-bit - Credential sha1 = Credential.getCredential("SHA-1:" + sha1Hex); // 160-bit
▼ 改造后（384 位，CNSA 2.0 推荐）

Realm 文件格式对应：alice: MD:SHA3-384:<96hex>, user（384 位）；需同步评估摘要长度增长对 DB 字段的影响（SHA3-384 为基准，SHA3-512 +33%）。
⚠️ 算法兼容性边界（迁移点 3）：HTTP Digest 是"无状态挑战-应答"协议，服务器发起 algorithm=SHA-384 挑战时无法预先探测客户端是否支持该算法——response 由客户端按挑战算法计算、服务器同算法复核。本测试客户端为自研 Java 客户端，只证明 Jetty setAlgorithm() 能驱动 SHA-384 走完整链路，不能证明真实第三方客户端（浏览器/curl 等）支持。且 SHA-384 并非 RFC 7616 注册算法（仅 MD5/SHA-256/SHA-512-256）。生产落地建议：多算法挑战 algorithm=SHA-384, algorithm=SHA-256 或跟随 RFC 7616 注册算法。
