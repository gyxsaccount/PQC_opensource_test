=== 迁移点4: Jetty 口令哈希 / Realm 迁移 (Password/Credential) ===
JDK: 27

[1] JCE 哈希算法可用性 + 摘要长度:
    MD5        [迁移前] OK, 128 bits (32 hex chars)
    SHA-1      [迁移前] OK, 160 bits (40 hex chars)
    SHA-256    [中间态] OK, 256 bits (64 hex chars)
    SHA-384    [迁移目标(384位)] OK, 384 bits (96 hex chars)
    SHA-512    [迁移目标] OK, 512 bits (128 hex chars)
    SHA3-256   [中间态] OK, 256 bits (64 hex chars)
    SHA3-384   [迁移目标(384位)] OK, 384 bits (96 hex chars)
    SHA3-512   [迁移目标] OK, 512 bits (128 hex chars)

[2] Jetty Credential.getCredential() 支持的前缀 (SPI+内置):
    CRYPT: -> Crypt [OK]
    MD5: -> MD5 [OK]
    MD:SHA-256: -> MD [OK]
    MD:SHA-384: -> MD [OK]
    MD:SHA3-256: -> MD [OK]
    MD:SHA3-384: -> MD [OK]
    MD:SHA3-512: -> MD [OK]

[3] Password 类生成/校验 (SHA3-384 迁移目标, 384 位):
    生成: MD:SHA3-384:9c1565e99afa2ce7800e96a73c125363c06697c5674d59f227b3368fd00b85ead506eefa90702673d873cb2c9357eafc
    校验正确密码: true, 校验错误密码: false
    => 迁移后哈希校验链路可用

[4] 摘要长度增长 (每 1000 万用户口令哈希, hex 存储, 基准=SHA3-384):
    算法                hex长度     相比SHA3-384
    ------------------------------------------------
    MD5                32     -67% (-203.5 MB @10M行)
    SHA-1              40     -58% (-222.5 MB @10M行)
    SHA-256            64     -33% (-203.5 MB @10M行)
    SHA-384            96     +0% (+0.0 MB @10M行)
    SHA-512           128     +33% (+406.9 MB @10M行)
    SHA3-256           64     -33% (-203.5 MB @10M行)
    SHA3-384           96     — (基准)
    SHA3-512          128     +33% (+406.9 MB @10M行)

[5] 说明:
    - 口令哈希本身并非量子直接威胁对象, 但 NIST/NSA 要求停止弱哈希 (MD5/SHA-1);
    - 迁移目标 (384 位): SHA-384 / SHA3-384, 与 Commons Codec 迁移一致;
    - 口令在线/离线暴破防护仍以 Argon2id/PBKDF2/BCrypt 为主 (算力型 KDF);
    - Jetty 通过 CredentialProvider SPI 可接入 Argon2id, 见 lib 目录扩展。

=== 迁移点4 结论: 口令哈希可平滑迁移到 SHA-384/SHA3-384 (384 位), 无阻断 ===
