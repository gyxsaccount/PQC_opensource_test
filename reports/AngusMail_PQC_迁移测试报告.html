④ 迁移点 P1：TLS 传输（SMTP / IMAP / POP3）

改造方式：Angus Mail 侧零代码改动，纯属性装配

// MailPqcConfig —— 三协议统一注入 PQC 套接字工厂 + TLSv1.3
p.setProperty("mail." + proto + ".ssl.enable", "true");        // 隐式 TLS
p.setProperty("mail." + proto + ".ssl.protocols", "TLSv1.3");
p.put("mail." + proto + ".ssl.socketFactory", new PqcSocketFactory()); // 实例注入
p.setProperty("mail." + proto + ".ssl.socketFactory.fallback", "false");

自定义套接字工厂（JDK/BC 双栈，握手前注入 PQC 群组）

public final class PqcSocketFactory extends SSLSocketFactory {
    public static SSLSocketFactory getDefault() {        // ★ Angus SocketFetcher 约定
        return new PqcSocketFactory();
    }
    public PqcSocketFactory() {                           // 无参构造（Angus 反射实例化）
        this.delegate = context.getSocketFactory();
        this.bc = PqcSsl.BC_JSSE.equals(context.getProvider().getName());
    }
    private Socket configure(Socket socket) {
        // BC: BCSSLParameters.setNamedGroups([X25519MLKEM768, x25519]) + setSignatureSchemes([mldsa65...])
        // JDK: SSLParameters.setNamedGroups([X25519MLKEM768, x25519])
        // 统一: setProtocols([TLSv1.3]) + handshakeCompletedListener 记录会话
    }
}

⑥ 迁移点 P3：S/MIME 式混合端到端加密

// 混合信封：ML-KEM-768 + RSA-OAEP → AES-256-GCM
KEM.Encapsulator enc = kem.newEncapsulator(mlkemPub);
KEM.Encapsulated cap = enc.encapsulate();
byte[] mlkemSs = cap.key().getEncoded();     // 后量子
byte[] rsaCt  = rsaCipher.doFinal(randomCek); // 经典兜底
byte[] cek = sha256(mlkemSs || sha256(randomCek));
AES-256-GCM(cek, data)                        // 内容加密
// 混合签名：ML-DSA-65 + Ed25519 双签名
Signature mldsa = Signature.getInstance("ML-DSA");
Signature ed    = Signature.getInstance("Ed25519");
// 两份签名都验证通过才有效（防量子伪造）
✅ 实测：明文 87B → 密文 1470B，解密还原=true；混合签名 5407B，验签=true；Angus Mail MimeMessage 承载密文往返成功。
说明：RFC 9629 / LAMPS 完成 PQC 证书与 CMS 混合格式标准化后，同一套原语嵌入 BC CMS/OpenPGP 即升级为标准 S/MIME。

⑨ 迁移断点与解决方案

#断点现象根因解决方案（切换依赖 / 自定义）状态
1SocketFactory 静态约定 仅无参构造 → NoSuchMethodException，回退默认工厂 → PKIX 失败 SocketFetcher 反射调用 getMethod("getDefault") 自定义：补 public static SSLSocketFactory getDefault() 已解决
2强制主机名校验 信任配置正确仍报 CERTIFICATE_UNKNOWN: No name matching localhost SocketFetcher 无条件设置 endpoint identification 自定义：证书 CN/SAN 含真实主机名（keytool -ext san=dns:localhost,ip:127.0.0.1） 已解决
3Sasl 服务注册机制 No authentication mechanisms supported by both server and client JDK 27 Sasl 不扫描应用 classpath 的 META-INF/services 切换：Security.addProvider(new PqcSaslProvider()) 注册 SaslClientFactory 已解决
4JDK 版本决定 JSSE PQC 能力 ML-DSA 证书在 JDK JSSE 握手失败；JDK 24-26 无 PQC 群组 SunJSSE signature_algorithms 硬编码无 mldsa 切换依赖：JDK<27 用 BC BCTLS；等待 IETF LAMPS 标准 有解·依赖BC
5writetimeout 包装层 设置 writetimeout 时原始 Socket 被包成 WriteTimeoutSocket SocketFetcher 写超时实现 自定义：演示工程不设 writetimeout；生产可保留 已解决
6octet-stream DCH 缺失 String 内容 writeTo 报 UnsupportedDataTypeException 无对应 DataContentHandler 切换：DataHandler(new ByteArrayDataSource(bytes,"application/octet-stream")) 已解决
